### high — Classic ASC stereo select reads CONTROL bit 0 instead of bit 1
- **Where:** `/home/gistarcade/src/POM68K/src/Asc.cpp:187`
- **Defect:** `const bool stereo = (regs_[0x02] & 1) != 0;` tests the analog/PWM-output bit; the ASC's stereo/mono bit is bit 1 (`MAME asc.cpp:92 static constexpr u32 CONTROL_STEREO = 1;` used as `BIT(m_regs[R_CONTROL], CONTROL_STEREO)` at asc.cpp:195/214/232, and the register map comment at asc.cpp:27 — "0x802: CONTROL (bit 0=analog or PWM output, 1=stereo/mono…)").
- **Trigger:** Classic-ASC machines (`MacIIMemory.h:136` and `RbvMemory.h:186` both build `AscV8 asc_{0x00}`; Mac II/IIx/IIcx, IIsi/IIci). Guest writes `$02` to `$F14802` for stereo → `stereo` is false → `tick()` never advances `rdB_`/`capB_`, never sets `STAT_HALF_B`/`STAT_EMPTY_OR_FULL_B`, right channel silently duplicates left, and the `capB == 0x1FF` half-empty edge IRQ (Asc.cpp:206-210) never fires, so FIFO B pins at 0x400. Inverse: a guest writing `$01` (PWM select, mono) makes POM68K drain the untouched FIFO B as the right channel and raise a `STAT_HALF_B` IRQ the real chip never raises.
- **Fix:** `const bool stereo = (regs_[0x02] & 0x02) != 0;`

### medium — Plus/SE/Classic RTC second is 60 video frames, not 7 833 600 CPU cycles (clock gains ~3.5 min/day)
- **Where:** `/home/gistarcade/src/POM68K/src/MacFrame.h:31`
- **Defect:** `if (++frameNo % 60 == 0) mem.tickOneSecond();` derives the RTC 1 Hz heartbeat (and the VIA CA2 one-second interrupt, `MacMemory.cpp:122-126`) from the 60.1474 Hz video timebase instead of the CPU/RTC clock.
- **Trigger:** Any Plus/SE/SE FDHD/Classic session. 60 × `kCyclesPerFrame` (130240) = 7 814 400 cycles = 0.997549 s at 7.8336 MHz, so the emulated RTC runs 1.002457× fast: +8.85 s per emulated hour, +212 s per emulated day, unbounded. On real hardware the 1 Hz CA2 pulse comes from the 343-0042's own 32.768 kHz crystal and is independent of video. Every other machine in the tree uses a cycle accumulator against the machine clock (`MacIIMemory.cpp:614-617`, `RbvMemory.cpp:469-470`, `CentrisMemory.cpp:554-557`, `Q700Memory.cpp:481-484`), and this drift is not among TODO.md's documented VIA/RTC gaps.
- **Fix:** Add `int64_t secAcc_` to `MacMemory` (reset in `reset()`), in `MacMemory::tick(int cpuCycles)` do `secAcc_ += cpuCycles; while (secAcc_ >= 7833600) { secAcc_ -= 7833600; tickOneSecond(); }`, and delete the `frameNo % 60` line from `MacFrameClock::runFrame` (keep `frameNo` for VBL phase).

### medium — miniaudio device never uninitialised on an `exit()` path: callback thread outlives the FloppySound statics it mixes from
- **Where:** `/home/gistarcade/src/POM68K/src/MacAudioHost.h:35` (class body 22-153)
- **Defect:** `void stop() { if (started_) ma_device_uninit(&device_); started_ = false; }` is the only teardown and the class declares no destructor, so any exit that bypasses `audioHost.stop()` (main.cpp:1049/1631) leaves miniaudio's playback thread running through static destruction.
- **Trigger:** The codebase explicitly hardens for third-party `exit()` during a session — main.cpp:1078-1081, "Any exit() while the thread runs (Xlib's default error handler exits behind GLFW's back)… `~LcMachine() { stop(); }`". On that path static destruction runs: `machine` (function-local static, main.cpp:1431) joins; `audioHost` (function-local static, main.cpp:1332) runs an implicit destructor that does nothing (`ma_device device_{}` is POD); then `gHddSfx`/`gFloppySfx` (namespace statics, main.cpp:358-359, constructed before `main` so destroyed last) are destroyed. The still-live callback then runs `fill()` → `fx->fillAudioBuffer(buf, n)` (MacAudioHost.h:131-144) → `drainCommands()`, which locks the destroyed `cmdMtx_` (`FloppySound.cpp:136-138`) and mixes from freed `samples_[i].data` — use-after-free on the real-time thread.
- **Fix:** `~MacAudioHost() { stop(); }` in MacAudioHost.h, and null the FX slots in `stop()` so any in-flight callback mixes nothing:
  ```cpp
  ~MacAudioHost() { stop(); }
  void stop() { if (started_) ma_device_uninit(&device_); started_ = false;
                fx_[0] = fx_[1] = nullptr; }
  ```

### low — Classic ASC does not decode $F09/$F29, returning 0 where hardware returns $01
- **Where:** `/home/gistarcade/src/POM68K/src/Asc.cpp:70-71`
- **Defect:** `AscV8::readReg`'s default arm computes `offset - 0x800` = `$709`/`$729` for offsets `$F09`/`$F29`, which is ≥ 0x20, so it returns 0; MAME `asc_base_device::read` (asc.cpp:334-337, inherited by the classic `asc_device`) returns `0x01` for `R_FIFOA_IRQCTRL`/`R_FIFOB_IRQCTRL`, and asc.h:52-74 places them at bus offsets `$F09`/`$F29`.
- **Trigger:** Any guest on Mac II/IIx/IIcx (`MacIIMemory.h:136`), IIsi/IIci (`RbvMemory.h:186`) or IIvx/IIvi (`VaspMemory.h:162`) probing the FIFO IRQ-control registers — the encoding ASCTester uses to distinguish ASC variants. It reads back 0, i.e. "enabled" in the IOSB/Sonora encoding, so a driver either skips arming the interrupts or misidentifies the chip. This is the project's own documented trap (comment block at Asc.cpp:301-307 and Asc.cpp:476-480); the two sibling flavors decode it (`AscIosb` Asc.cpp:308/310, `AscSonora` Asc.cpp:482-483) and `AscV8` was left out.
- **Fix:** at the top of `AscV8::readReg`, before the switch: `if (classic() && (offset == 0xF09 || offset == 0xF29)) return 0x01;`

### low — V8 pseudo-VIA ASC semantics applied unconditionally to the RBV and VASP machines
- **Where:** `/home/gistarcade/src/POM68K/src/PseudoVia.cpp:51` and `:109-112`
- **Defect:** `PseudoVia` hardcodes the V8 override — `v &= uint8_t(~0x10);` swallows the guest's ack of IFR bit 4, and `recalcIrqs()` re-latches `ascLine_` on every pass — but MAME wires the Mac IIci/IIsi (`rbv.cpp:66 APPLE_PSEUDOVIA`) and the Mac IIvx/IIvi (`vasp.cpp:90 APPLE_PSEUDOVIA`) to the *base* device, where `asc_irq_w` latches only the 0→1 transition (`pseudovia.cpp:136-146`, guarded by `m_live_main_ints`) and write case 0x03 has no `data &= ~0x10` mask (pseudovia.cpp:268-271). Only V8/Eagle/Spice/Tinker Bell (`v8.cpp:124`) and Sonora (`sonora.cpp:80`) get the level flavour.
- **Trigger:** IIvx/IIvi pair a V8-flavour ASC (`VaspMemory.h:162 AscV8 asc_;` → version `$E8`, level-sticky: `tick()` re-asserts on every sample with `cap_ < 0x200`, Asc.cpp:244-247, and `$804` refuses to drop it while `STAT_HALF_A` is set, Asc.cpp:64-66) with this V8 pseudo-VIA, so once the guest enables pseudo-VIA IER bit 4 the ASC interrupt can never be acknowledged — the ack is discarded and the level re-applied after every RTE, the same shape as the "Bienvenue." livelock documented at Asc.cpp:463-473. On MAME's VASP the base device latches the rise once and the ack sticks.
- **Fix:** give `PseudoVia` a flavour flag set by the owner; for `RbvMemory`/`VaspMemory` select Base — edge-latch (`if (state && !ascLine_) regs_[3] |= ASC; ascLine_ = state;` with no re-sample in `recalcIrqs()`) and drop the `v &= ~0x10` mask in write case 0x03. `V8Memory`/`SonoraMemory` keep today's level behaviour.

*Dropped after re-check:* the "PseudoVia read decodes only A0/A1/A4, aliasing Sonora registers 4/5" claim — `onConfigRead` is installed only by `V8Memory.cpp:25`, so on Sonora machines offsets 4 and 5 alias onto registers that both read back 0, matching MAME's zeroed regs 4/5; no observable divergence.
